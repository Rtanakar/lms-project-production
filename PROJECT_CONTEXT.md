# LMS Production — Project Context

> **Purpose**: Single source of truth for resuming work across sessions / context windows. Read this top-to-bottom on any new chat — covers stack, structure, decisions, endpoints, conventions, gotchas, and what's next.

## 0. Quick orientation

- **What**: Production LMS (Sheryians / Theo-style) — courses marketplace + auth + future lessons/payments
- **Repo layout**: NOT a monorepo. Two independent projects side-by-side:
  - `api/` — Express + TS backend
  - `web/` — Next.js 16 frontend
- **Communication style**: Hinglish in chat + Hinglish code comments (in English: content/strings, comments mostly Hinglish)
- **User preference**: Step-by-step confirmation, production-grade code, no over-engineering until needed
- **Today's date assumption**: ~ May 2026

## 1. Tech stack (locked)

### Backend (`api/`)

- **Runtime**: Node 20+, **TypeScript 6** (preview), pnpm
- **Framework**: Express **5.2** (path-to-regexp v8)
- **DB**: Postgres + **Prisma 7** (PG adapter, output → `src/generated/prisma`)
- **Auth**: **Better Auth 1.6** + Prisma adapter + Upstash Redis secondaryStorage
- **Validation**: **Zod 4**
- **Logger**: **Pino** + pino-pretty (dev) + morgan→pino bridge
- **Storage**: **Cloudflare R2** (S3-compatible) via `@aws-sdk/client-s3` + `s3-request-presigner`
- **Email**: **Resend** + React Email templates
- **Queue (future)**: BullMQ + Upstash Redis — Phase 11.6 (lessons)
- **Video (future)**: Mux — Phase 11.6 (lessons)
- **Errors**: **Sentry** (`@sentry/node` + `@sentry/profiling-node`)
- **Security**: Helmet 8 + custom `permissionsPolicy` / `noStoreCache` / `requestId` / `responseTime` middleware

### Frontend (`web/`)

- **Framework**: **Next.js 16** (Turbopack default, async cookies/params/searchParams, `proxy.ts` replaces `middleware.ts`)
- **React 19** + TypeScript 5
- **UI**: shadcn (radix-nova style) + Tailwind v4 + lucide-react + **motion** (formerly framer-motion)
- **State**: **Zustand** (client) + **TanStack Query 5** (server) — Redux NOT used
- **Forms**: React Hook Form + Zod resolver
- **Toasts**: sonner
- **Theme**: next-themes (dark base)
- **No**: tRPC, gRPC, NestJS, superjson as global transformer (kept locally for hydration boundaries only)

### Brand

- Primary: `#FF5A1F` (orange) / `#E04A12` (dark orange) / `#FFB07A` (peach)
- Cream tones: `#FFF7EC`, `#F7EBD6`
- Ink: `#0E0A07`, `#3A2E22`, `#6B5B4A`
- Background: `#0A0807` (auth + courses listing)

## 6. Conventions & patterns to follow

### Response shape (always)

```ts
// Success
{ success: true, data: <T> }

// Error (from errorHandler middleware)
{ success: false, error: { code: "ERROR_CODE", message: "..." } }
// 400 ZodError adds: error.issues: [{ path, message }]
```

### Service / controller split

- **Controllers**: HTTP shape only — extract `req.validated`, call service, send response
- **Services**: business logic + DB queries + authz guards (defense in depth)
- **Validators**: Zod schemas + `z.infer<>` type exports
- **Routes**: `requireAuth → requireRole → validate → controller` chain

### Prisma typing

Always type dynamic Prisma queries explicitly:

```ts
const where: Prisma.CourseWhereInput = { ... };
const orderBy: Prisma.CourseOrderByWithRelationInput = { ... };
// Use Prisma.QueryMode.insensitive, NOT "insensitive" as const
```

### Express Request augmentations (`src/@types/express.d.ts`)

```ts
req.id; // requestId middleware (UUID)
req.validated; // validate middleware (Zod parsed body/query/params)
req.user; // requireAuth middleware (Better Auth User)
req.session; // requireAuth middleware (Better Auth Session)
```

NEVER re-declare `Request` in feature files — central augmentation only.

### Express 5 wildcards

- Express 5 uses **path-to-regexp v8** — `*` standalone is invalid
- Use `app.all("/api/auth/{*any}", handler)` for named optional wildcard
- Better Auth mount in app.ts uses this pattern

### Better Auth signin

- Cookies work cross-port on `localhost` (same hostname → cookies shared by port)
- Postman MUST send `Origin: http://localhost:3000` header (Better Auth CSRF check)
- CORS: `credentials: true` + `exposedHeaders: ["Set-Cookie"]`

### Soft-verify auth pattern (active)

- `autoSignIn: true` — signup → session immediate
- `requireEmailVerification: false` — can signin without verify
- Verification email sent in background via Better Auth hook
- App-level gates (course enrollment, etc.) check `user.emailVerified` separately

### Hinglish comments style

- Code comments: Hinglish (`Yaha se start hota hai...`, `Ye field updateable hai...`)
- File header docstring: title + 1-2 line summary
- User-facing strings (emails, UI labels): English
- Field names + variables: English

### Slugify pattern

- User can provide slug or it's auto-generated from title
- `uniqueSlugify` appends `-2`, `-3` etc. if taken
- Slug max length 80, kebab-case, NFKD normalized

### Presigned upload pattern (industry standard)

1. Frontend: POST `/api/v1/uploads/presigned` with `{ kind, contentType, filename, sizeBytes }`
2. Backend validates MIME + size against kind allowlist
3. Returns `{ uploadUrl, publicUrl, key, headers }`
4. Frontend PUTs file directly to R2 with required headers
5. Frontend uses `publicUrl` in form / TipTap content
6. Server stores `publicUrl` in DB (not the file)

### Async cookies (Next.js 16)

- `cookies()`, `headers()`, `params`, `searchParams` are ALL async — must `await`
- `cookies()` returns request-scoped cookies (sent by browser)
- `localhost:3000` and `localhost:8080` SHARE cookies (cookie domain is hostname not host:port)

## 7. Common gotchas / debugging notes

| Issue                                     | Cause                                    | Fix                                                     |
| ----------------------------------------- | ---------------------------------------- | ------------------------------------------------------- |
| `MISSING_OR_NULL_ORIGIN` in Postman       | Better Auth CSRF check                   | Add `Origin: http://localhost:3000` header              |
| `404 Cannot POST /api/auth/sign-up/email` | Express 5 wildcard syntax                | Use `/api/auth/{*any}` (already fixed in app.ts)        |
| Session table empty after signup          | `autoSignIn: false` was set              | Switch to `autoSignIn: true` (already done)             |
| `Property 'id' does not exist on Request` | Augmentation in wrong file               | Add to `src/@types/express.d.ts` only (central)         |
| Prisma `where` type error                 | Inline object without explicit type      | Type as `Prisma.CourseWhereInput`                       |
| Pino "≡ƒÄë" garbage in Windows console    | Emoji + Windows cp1252 console           | Removed emoji from startup-banner                       |
| Email "skipped (dev mode)"                | RESEND_API_KEY not set or no real domain | Set RESEND_API_KEY + verified domain                    |
| TopNav refresh doesn't show new user      | Server component cache                   | `router.refresh()` after sign-in                        |
| Footer cursor-reveal not following        | Mouse tracking missing                   | onMouseMove sets `--mx`/`--my` CSS vars, mask uses them |

## 12. Decision log (why we picked X over Y)

| Decision                                   | Reasoning                                                                  |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| Express over NestJS                        | User preference + lighter, no decorators learning curve                    |
| REST over tRPC/gRPC                        | Frontend + backend in separate repos; REST cleaner across boundaries       |
| Zustand over Redux Toolkit                 | LMS is not Figma — server state via TanStack Query, client state minimal   |
| Better Auth over NextAuth                  | Type-safe, modern, plugins (admin, polar), framework-agnostic              |
