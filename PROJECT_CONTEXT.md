## 1. Tech stack (locked)

### Backend (`api/`)

- **Runtime**: Node 20+, **TypeScript 6** (preview), pnpm
- **Framework**: Express **5.2** (path-to-regexp v8)
- **DB**: Postgres + **Prisma 7** (PG adapter, output → `src/generated/prisma`)
- **Architecture**: **Feature modules + Layered (Controller → Service → Repository → Prisma)** — see §6
- **Auth**: **Better Auth 1.6** + Prisma adapter + Upstash Redis secondaryStorage
- **Validation**: **Zod 4**
- **Logger**: **Pino** + pino-pretty (dev) + morgan→pino bridge
- **Storage**: **Cloudflare R2** (S3-compatible) via `@aws-sdk/client-s3` + `s3-request-presigner`
- **Email**: **Resend** + React Email templates
- **Queue (future)**: BullMQ + Upstash Redis — Phase 11.6 (lessons)
- **Video (future)**: Mux — Phase 11.6 (lessons)
- **Errors**: **Sentry** (`@sentry/node` + `@sentry/profiling-node`)
- **Security**: Helmet 8 + custom `permissionsPolicy` / `noStoreCache` / `requestId` / `responseTime` middleware

### Frontend (`web/`)

- **Framework**: **Next.js 16** (Turbopack default, async cookies/params/searchParams, `proxy.ts` replaces `middleware.ts`)
- **React 19** + TypeScript 5
- **UI**: shadcn (radix-nova style) + Tailwind v4 + lucide-react + **motion** (formerly framer-motion)
- **State**: **TanStack Query 5** (server state) + **nuqs** (URL state) + React Context (auth user) — **Zustand NOT used, Redux NOT used**
- **Forms**: React Hook Form + Zod resolver
- **Toasts**: sonner
- **Theme**: next-themes (dark base)
- **No**: tRPC, gRPC, NestJS, superjson global transformer, Zustand, Redux

### Brand

- Primary: `#FF5A1F` (orange) / `#E04A12` (dark orange) / `#FFB07A` (peach)
- Cream tones: `#FFF7EC`, `#F7EBD6`
- Ink: `#0E0A07`, `#3A2E22`, `#6B5B4A`
- Background: `#0A0807` (auth + courses listing + dashboard)

## 6. Conventions & patterns to follow

### Response shape (always)

```ts
// Success
{ success: true, data: <T> }

// Error (from errorHandler middleware)
{ success: false, error: { code: "ERROR_CODE", message: "..." } }
// 400 ZodError adds: error.issues: [{ path, message }]
```

### ⭐ Backend architecture — Feature modules + Layered

**Per-feature folder** under `src/modules/<feature>/` contains 5 files:

```
modules/courses/
├── course.controller.ts    ← HTTP shape — extract req.validated, call service, send response
├── course.service.ts       ← Business logic + authz guards (defense in depth)
├── course.repository.ts    ← ONLY layer touching prisma.* — ALL DB ops go through repo
├── course.routes.ts        ← requireAuth → requireRole → validate → controller chain
└── course.validator.ts     ← Zod schemas + z.infer types
```

**Strict rules:**

1. **Controllers** NEVER touch Prisma, services, or DB. Just HTTP.
2. **Services** NEVER call `prisma.*` directly — always via repository methods. Services orchestrate business rules + authz.
3. **Repositories** are the ONLY place `prisma.course.*` etc. appears.
4. **Validators** export Zod schemas + `z.infer<>` types.
5. **Routes** wire up middleware chain: `requireAuth → requireRole → validate({...}) → controller.x`.

**Aggregate root**: One repo per aggregate (Course is root, Module + FAQ are children). All three CRUD ops in `courseRepository`.

**Why this pattern?**

- Service testable in isolation (mock repo, not Prisma)
- Feature cohesion (one folder per domain)
- Scales to 50+ features without files-in-same-folder fatigue
- Industry-standard (NestJS-inspired, used by Linear, Cal.com, similar Node apps)

### Prisma typing

Always type dynamic Prisma queries explicitly:

```ts
const where: Prisma.CourseWhereInput = { ... };
const orderBy: Prisma.CourseOrderByWithRelationInput = { ... };
// Use Prisma.QueryMode.insensitive, NOT "insensitive" as const
```

### Express Request augmentations (`src/@types/express.d.ts`)

```ts
req.id; // requestId middleware (UUID)
req.validated; // validate middleware (Zod parsed body/query/params)
req.user; // requireAuth middleware (Better Auth User)
req.session; // requireAuth middleware (Better Auth Session)
```

NEVER re-declare `Request` in feature files — central augmentation only.

### Express 5 wildcards

- Express 5 uses **path-to-regexp v8** — `*` standalone is invalid
- Use `app.all("/api/auth/{*any}", handler)` for named optional wildcard
- Better Auth mount in app.ts uses this pattern

### Better Auth signin

- Cookies work cross-port on `localhost` (same hostname → cookies shared by port)
- Postman MUST send `Origin: http://localhost:3000` header (Better Auth CSRF check)
- CORS: `credentials: true` + `exposedHeaders: ["Set-Cookie"]`

### Soft-verify auth pattern (active)

- `autoSignIn: true` — signup → session immediate
- `requireEmailVerification: false` — can signin without verify
- Verification email sent in background via Better Auth hook
- App-level gates (course enrollment, etc.) check `user.emailVerified` separately

### Hinglish comments style

- Code comments: Hinglish (`Yaha se start hota hai...`, `Ye field updateable hai...`)
- File header docstring: title + 1-2 line summary
- User-facing strings (emails, UI labels): English
- Field names + variables: English

### Slugify pattern

- User can provide slug or it's auto-generated from title
- `uniqueSlugify` appends `-2`, `-3` etc. if taken
- Slug max length 80, kebab-case, NFKD normalized

### Presigned upload pattern (industry standard)

1. Frontend: POST `/api/v1/uploads/presigned` with `{ kind, contentType, filename, sizeBytes }`
2. Backend validates MIME + size against kind allowlist
3. Returns `{ uploadUrl, publicUrl, key, headers }`
4. Frontend PUTs file directly to R2 with required headers
5. Frontend uses `publicUrl` in form / TipTap content
6. Server stores `publicUrl` in DB (not the file)

### Async cookies (Next.js 16)

- `cookies()`, `headers()`, `params`, `searchParams` are ALL async — must `await`
- `cookies()` returns request-scoped cookies (sent by browser)
- `localhost:3000` and `localhost:8080` SHARE cookies (cookie domain is hostname not host:port)

### ⭐ Frontend state pattern (NO Zustand, NO Redux)

- **Server state**: TanStack Query 5 (queries + mutations + cache invalidation)
- **URL state**: nuqs (search params persisted to URL — search, filters, page, sort)
- **Auth/user**: `CurrentUserProvider` (React Context, server-seeded — `features/auth/hooks/use-current-user.tsx`)
- **Forms**: React Hook Form + Zod resolver (each form has local `useForm`)
- **Tiny UI state**: `useState` in component (modal open, dropdown, etc.)

**Why not Zustand?** Server state handled by TanStack Query. URL state by nuqs. Auth by Context. Form state by RHF. There's no global client state left worth a store. Linear, Vercel, Cal.com use this same approach.

### ⭐ Current user pattern (web)

- Server layout (`app/dashboard/layout.tsx`) calls `getServerSession()` → seeds `<CurrentUserProvider initial={session.user}>`
- Client components read via `useCurrentUser()` — same data SSR + first client render → ZERO hydration mismatch
- Optimistic updates: `useCurrentUserActions().patch({ name })` after successful PATCH → UI updates instantly without refetch
- Avatar / name changes propagate to sidebar + header in same tick

### ⭐ Pagination pattern (cursor + offset hybrid)

- Default: cursor pagination for stable next-page (no drift on inserts)
- Fallback: offset pagination for "jump to page N" UX (numbered pagination)
- `PaginationControls` component: dropdown for ≤10 pages, number input for >10 pages (industry standard)
- Server hooks return `{ items, nextCursor, totalCount, totalPages, hasNextPage, hasPreviousPage, pagination }`
- Client hook tracks `cursorHistory[]` for "previous" support
- Backend repository: `take + 1` trick → no extra count for hasNextPage; `id` as secondary sort for cursor stability; cursor mode uses `cursor + skip:1`, offset mode uses `skip: (page-1)*limit`

### ⭐ Server-prefetch + Suspense pattern (Netflix/Vercel/Linear)

For dashboard pages that need fast first-paint with no loading spinner:

```tsx
// page.tsx (server component)
await requireRole("INSTRUCTOR", "ADMIN");
const params = await xxxParamsCache.parse(searchParams);
prefetchXxx(apiQuery); // fire-and-forget — Suspense waits

return (
  <XxxContainer>
    {" "}
    {/* layout chrome — renders instantly */}
    <HydrateClient>
      <ErrorBoundary FallbackComponent={XxxError}>
        <Suspense fallback={<XxxLoading />}>
          <XxxContent /> {/* useSuspenseQuery → reads hydrated cache */}
        </Suspense>
      </ErrorBoundary>
    </HydrateClient>
  </XxxContainer>
);
```

- `HydrateClient` (`lib/hydrate-client.tsx`) — generic `HydrationBoundary` + `dehydrate(getQueryClient())`
- `prefetchXxx` — server-side cookies forwarded via `api()` `cookie` param + same `queryKey` as client hook → cache hit, zero refetch
- `useSuspenseQuery` in Content → no loading state needed (cache already filled)
- Skeleton in `XxxLoading` (not spinner) — perceived perf
- `ErrorBoundary` catches both render errors AND query errors (TanStack `throwOnError`)

### ⭐ nuqs URL state — single-file pattern

- ONE file per feature: `features/<x>/server/params-loader.ts`
- Exports both `xxxParams` (for client `useQueryStates`) + `xxxParamsCache` (for server `.parse(searchParams)`)
- DRY: schema change → ek jagah update, dono sides aligned
- `clearOnDefault: true` — default value === drop from URL → clean shareable links

## 12. Decision log (why we picked X over Y)

| Decision                                                 | Reasoning                                                                                                          |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Express over NestJS                                      | User preference + lighter, no decorators learning curve                                                            |
| REST over tRPC/gRPC                                      | Frontend + backend in separate repos; REST cleaner across boundaries                                               |
| ⭐ Feature modules + repositories (Path B)               | NestJS-inspired, scales to 50+ features; service testable via repo mock; chosen over flat structure for long-term  |
| ⭐ TanStack Query + nuqs + Context (no Zustand)          | Server state by TanStack Query, URL state by nuqs, auth by Context, form by RHF — leaves no global state for store |
| Better Auth over NextAuth                                | Type-safe, modern, plugins (admin, polar), framework-agnostic                                                      |
| Cloudflare R2 over AWS S3                                | FREE egress (vs ~$0.09/GB on S3) — huge cost saving for video delivery                                             |
| R2 over Mux (for now)                                    | One demo video doesn't justify Mux setup; switch when lessons added                                                |
| Upstash Redis REST over ioredis                          | Better Auth secondaryStorage uses REST; ioredis kept for future BullMQ                                             |
| Soft-verify (autoSignIn) over verify-first               | Modern SaaS pattern — Vercel/Linear/GitHub do this for higher conversion                                           |
| TipTap JSON in Postgres `Json` column                    | Updateable rich content without schema migrations                                                                  |
| Slug + ID dual identifier                                | Slug for public URLs (SEO), ID for admin operations                                                                |
| Hex colors in emails                                     | Outlook butchers oklch/hsl — hex only for email-client compat                                                      |
| ⭐ CurrentUserProvider (server-seeded) over useSession() | Zero hydration mismatch, no refetch waterfall, optimistic patches possible                                         |
| ⭐ Cursor + offset hybrid pagination                     | Cursor for stable next/prev, offset for "jump to page" UX (PaginationControls supports both)                       |
| ⭐ Smart pagination UI (dropdown ≤10 / input >10)        | Dropdown unwieldy past 10 pages — Linear/Vercel pattern                                                            |
